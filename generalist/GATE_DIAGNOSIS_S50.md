# 门控双半脑 step-50 诊断：门为什么不分

- 检查点：`out/generalist3_d1024_s300_last.npz`，step 50，last_train_loss 5.3757（step 1 是 9.3316）
- 诊断时间：2026-11-16 ~23:55 EST；训练已被用户叫停（运行时重启打断在 step 60，_last 为 step 50）
- 诊断脚本：`diagnose_gate_s50.py`（只读；LEAN 加载，只读 p_* 参数；batch 2/4），输出 `gate_diag_s50.log`
- 背景探针：step 25 分离 0.0054（6 域全 ~0.51）；step 50 分离 0.0155（左均值 0.5310，世界 0.5155）

## 根因（一句话）

**门看不到域**：`g = sigmoid(emb[token] · W + b)`，是单个词的查表值——不含位置、不含上下文、不含序列信息；域是整段话的属性，门却只能按词查表，所以 BCE 监督在共享词上是自相矛盾的，门在数学上就不可能分化。

机制（`dual_transformer_numpy.py` `_forward`，三份字节一致，md5 14b8df60194addfa73f43c429a433ee7）：

```python
x = self.params["emb"][tokens]          # pos_mode='rope'，没有 wpe 位置项
z = x @ self.params["gate.weight"].T + self.params["gate.bias"]
g = sigmoid(z)                           # 在任何 transformer block 之前算出
branch_x = {"left": g * x, "right": (1 - g) * x}
merged = g * outs["left"] + (1 - g) * outs["right"]
```

注意：设计文档说的是"token embedding（+ learned 位置编码）"，实际配置 `pos_mode='rope'`，所以**连位置都没有**——同一个词在任何位置、任何域、任何上下文里，g 完全相同。比原假说更强。

## 证据

### 测试 1：同词测试——门不含域信息（除词本身外）

直接算 g（与 `gate_values()` 全前向逐位一致，max diff = 0.000e+00）：

| 检查 | 结果 |
|---|---|
| 同词 `"`（id 4）：经典窗口 pos 11 vs 世界窗口 pos 56 | g 都是 0.567380，diff = 0.00e+00 |
| 上下文替换：`#` 在 pos 64，原窗口 / 世界上下文 / 随机上下文 | g 都是 0.598445，diff = 0.00e+00 |
| 位置无关：`的` 在 pos 0/32/64/127 | 都是 0.543213，spread = 0.00e+00 |
| 共享功能词 g | 的 0.5432、是 0.5566、在 0.4983、人 0.5082、了 0.5212、我 0.5171、你 0.5133、他 0.5301、不 0.5286、有 0.5166、这 0.5261——全在 0.5 附近 |

- 结论：**没有任何一个词的 g 接近 0 或 1**，门没有表达分化的数值空间。

|---|---|---|---|---|
| 经典 | 6.9908 | 6.9992 | 7.0411 | +0.0502 |
| 代码 | 4.7859 | 4.7889 | 4.9267 | +0.1408 |
| 对话 | 3.6762 | 3.6740 | 4.6382 | **+0.9620** |
| 常识 | 7.2008 | 7.2065 | 7.2544 | +0.0536 |

- **强制 0.5 与学到的门处处差 ≤ 0.013**（世界域强制 0.5 甚至略好：4.3353 < 4.3449）——学到的门在功能上就是一个常数 0.5，50 步训练没有给它任何信息量。
- 强制监督目标平均贵 +0.40（左）/+0.54（世界）；代价最大的正是模型拟合得最好的域（对话、推理）——两个分支在 g≈0.5 下共同编码了内容，砍掉一个分支最疼。
- 注意：这个代价 partly 是"分支从未在极端 g 下训练过"的分布偏移，不全是"LM 反对分化"；LM 反对的干净证据见测试 4。

### 测试 4：门梯度分解——BCE 监督在工作，但自己打自己

一个 batch（3 左 + 1 世界，seq 128），两次 `loss_and_grads`（gate_loss_weight=1.0 vs 0.0，相减分离）：

- batch mean g=0.5292；mean(g−t)：左 token −0.4637，世界 token +0.5078——BCE 信号又大又对称。
- total loss 5.3882，LM loss 4.7424，BCE loss 0.6458（常数预测约 0.67——门只比常数好一点）。
- `gate.weight`：‖LM‖=0.0126，‖BCE‖=0.0436，‖net‖=0.0423，**cos(LM, BCE)=−0.243**，BCE/LM=3.46。
- `gate.bias`：‖LM‖=0.0170，‖BCE‖=0.2208，‖net‖=0.2378，cos=+1.000（标量，同号），BCE/LM=12.97。

解读：

1. **接线没问题，监督够强**——BCE 梯度是 LM 梯度的 3.5 倍（weight）/13 倍（bias）。门不分不是因为监督太弱。
2. **监督自相矛盾**：同一个共享词在左 batch 被推向 1、在世界 batch 被推向 0；净方向由词的域频率 profile 定。左域占 85%，净漂移向上——与观测一致（两域均值都在 0.5 之上、左略高；bias 已从 0 漂到 +0.0492，约等于 50 步 × lr≈1e-3 的最大漂移，即 bias 几乎每步都在朝同一个方向走）。
3. **LM 轻度反对**：weight 子空间上 cos=−0.243，LM 抵消了 BCE 约 14% 的平方量级；bias 上 LM 与 BCE 同向（都在推 g 向上），不是反对。LM 不是主因，主因是门没有信息。
4. 直觉模型（非严格证明）：只看 BCE 时，每个词的平衡点约等于它在左 batch 里出现的频率占比；共享词的占比都接近混合比 85/15，所以全词表挤在 0.46–0.60 之间。想分化，门必须能看到"这段话是哪个域"，而它现在只能看到"这个词是哪个字"。

## 排除项（已验证不是这些问题）

- 不是接线 bug：`make_batch_fn` 返回 gate 目标（左 1.0 / 世界 0.0），`train_steps` 传给 `loss_and_grads`，BCE 已接入总 loss；测试 4 证实 BCE 梯度真实存在且主导门梯度。
- 不是 gate-loss-weight 太小：weight=1.0 时 BCE 已是 LM 的 3.5–13 倍；再加大只会让共享词被推得更狠，不会产生序列级分化。
- 不是训练步数不够：50 步里 bias 已漂到 LR 允许的最大值附近；分离度 0.0054→0.0155 的缓慢增长是同一漂移的延续，不是分化在酝酿。门的值域本身（全词表 [0.46, 0.60]）就不支持分化，再跑 250 步也只能在同一区间里挪。
- 不是 checkpoint/加载问题：探针用 LEAN 加载（只读 p_*），与 `gate_values()` 全前向逐位一致。

## 修复方案（按推荐度排序）

### 1. 每序列一个门，从池化表示算（首选，改动最小）

- 门的输入改成序列级池化表示：`g_seq = sigmoid(w · mean_pool(emb) + b)`，形状 (B,1,1)，同一序列内所有 token 共用一个 g；输入分流与输出混合仍用这个 g。
- 为什么能修：池化后的词频 profile 携带域信息（各域词分布不同），线性门就能分开；监督本身已经是每序列一个目标（trainer 里 gate 是每序列常数），现在门与监督终于在同一粒度上。
- 工作量：`_forward` 里门计算改几行；`gate_values` / 探针相应改成序列级；`loss_and_grads` 的门梯度公式不用动（dz_gate 仍是 (B,S,1)，只是各位置相同）。
- 验证标准：3 步 pilot 后探针——左域 mean g 应明显 >0.6、世界 <0.4；step 25 分离度应 >0.2，否则再诊断。预期：池化线性分类域几乎立刻能分，不需要等 50 步。

### 2. 门从上下文 hidden state 算（更彻底，改动较大）

- 先过一个共享 stem（例如第 0 个 block 共享，或在分支前加一个小的共享投影），门从 stem 的 hidden state 算：`g = sigmoid(h_stem @ W + b)`，仍可每 token 一个 g，但这次它看到了上下文。
- 为什么能修：门获得了序列上下文，能判断"这段话在讲什么"；同时保留每 token 粒度（一段话里可混域）。
- 代价：分流点后移，架构改动比方案 1 大（共享 stem + 门位置移动 + 梯度路径变化）；需要重验数值梯度与 checkpoint 兼容性（旧 gated 断点不能直接用）。
- 适用：如果方案 1 的池化门分离度不够（例如域间词频 profile 太像），再上这个。

### 3. 提高 gate-loss-weight / 退火（不推荐作为修复，只作诊断验证）

- 把 `--gate-loss-weight` 从 1.0 提到 5–10，或先高后低退火。
- 为什么不能修根因：监督的矛盾在 token 粒度上，加大权重只会让共享词被推得更狠、平衡点挪一点点（值域 0.46–0.60 至多扩到 0.40–0.65），产生不了序列级分化；同时会扭曲分支输入、拖累 LM loss。
- 唯一价值：便宜的验证——如果提 10 倍后分离度仍 <0.05，就进一步坐实"信息缺失、非权重问题"。不建议为此单独烧一个 19.5 小时的块；3 步 pilot 足够看趋势。

补充说明（不在上面三条里）：

- "只在输出端用门"（去掉输入分流）本身修不了信息问题——门还是看不到域；它只有与方案 1/2 结合时才有意义（让分支专精化）。如果方案 1 落地，可顺带评估去掉输入分流是否让分支分工更干净。
- 任何方案落地前都应先做 3 步 pilot + 探针：门分离是"有/无"的二值信号，3 步足够判断，不需要烧完整块。
- 本诊断未动的：训练未续跑；trainer、模型、语料、检查点均未修改（测试 3 的门参数覆盖只在内存内，事后恢复）。
